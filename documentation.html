Project Overview

Impact Self Defense Academy is a static marketing website for a karate and self-defense school in Agra, Uttar Pradesh. It is a single-page site with no build step, no framework, and no dependencies — pure HTML, CSS, and vanilla JavaScript.

Frontend

HTML

  • Semantic HTML5 — <header>, <main>, <footer>, <section>, <article>, <address>, <details>
  • Full accessibility: skip link, ARIA labels, aria-expanded on hamburger, role="dialog" on lightbox
  • SEO: <meta> description, Open Graph, Twitter Card, canonical URL
  • Structured data: JSON-LD with LocalBusiness and FAQPage schemas
  • Performance: loading="lazy" on images, <link rel="preload"> for hero image, preconnect for Google Fonts

JavaScript

Vanilla ES2020+, no libraries. Single script.js loaded at end of <body>.

CSS

Pure CSS3. No preprocessor, no framework (no Bootstrap). Single styles.css file.

Layout

  • CSS Grid — programs grid (3-col), gallery grid (masonry-style), facilities, FAQ, contact, footer
  • Flexbox — navbar, hero stats bar, buttons, cards
  • Container: width: min(1200px, 100% - 2rem) — responsive without media queries
  • Fluid spacing: clamp() for section padding, font sizes, and gaps

Visual Effects

  • Glassmorphism: backdrop-filter: blur() on scrolled navbar and gallery overlay
  • Scroll reveal: IntersectionObserver adds .visible class to .reveal elements
  • Hero shapes: Absolutely-positioned decorative rings using CSS borders
  • Gradient text: -webkit-background-clip: text on "DEFEND." in hero
  • Stat counters: JS setInterval animated number count-up on viewport entry

Design Tokens

All design decisions are encoded as CSS custom properties in :root. There is no separate token file — the source of truth is the top of styles.css.

Critical: transform: translateZ(0) on a position: fixed parent creates a new stacking context — its fixed children become positioned relative to it, not the viewport. This is why .site-header does not use any CSS transform.

GitHub Pages

The site is deployed to GitHub Pages from the gh-pages branch, which is auto-populated by the CI/CD workflow on every push to master.

Pages Source

Branch: gh-pages · Root: / (root)

After any push to master, allow ~1–2 minutes for GitHub Actions to build and GitHub Pages to propagate.

CI/CD Workflow

File: .github/workflows/deploy.yml

name: Deploy to GitHub Pages

on:
  push:
    branches: [master]
  workflow_dispatch:

permissions:
  contents: write        # Required: lets the action push to gh-pages branch

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: .
          exclude_assets: '.github,angular,old-website,new-html-website,.netlify,.netlifyignore,netlify.toml,README.md'

Why peaceiris/actions-gh-pages?

The native actions/deploy-pages action requires a github-pages environment configured in repo settings. peaceiris/actions-gh-pages@v3 works with just a GITHUB_TOKEN and contents: write permission — simpler and more reliable for this repo's setup.

Netlify (Legacy)

The site was originally deployed to impactselfdefenseacademy.netlify.app. It was migrated to GitHub Pages after Netlify build credits were exhausted.

The Netlify config (netlify.toml) remains in the repo as a fallback:

[build]
  publish = "."
  command = ""            # No build step — static files served directly
Netlify can be reactivated at any time by running: netlify deploy --prod --dir . (direct deploy bypasses build minutes entirely).

Mobile Nav — Fix History

The mobile navigation went through several iterations to resolve a menu-hidden-behind-content issue.

1

Problem: Nav items floating centered

Base .nav-menu had align-items: center. Fixed by adding align-items: stretch in mobile breakpoint and display: block; width: 100% on list items.

2

Problem: Menu hiding behind page content

Sections with CSS animations or transforms create new stacking contexts. Fixed by bumping all nav z-indices to the 8998–9001 range.

3

Problem: overflow: hidden on <html> clipping nav

overflow: hidden on the root element clips position: fixed children in some browsers. Switched to body-only.

4

Problem: Gallery images showing through nav on iOS Safari

overflow: hidden on <body> causes fixed elements to lose background rendering on iOS Safari. Final fix: removed all body/html overflow manipulation. The nav overlay uses touch-action: none to block touch scrolling via CSS instead.

CSS Gotchas

transform + position:fixed — Any CSS transform, filter, or will-change on a position: fixed ancestor makes that ancestor a containing block for its fixed descendants. They are no longer viewport-relative. This is why .site-header uses no transforms (hardware acceleration via translateZ(0) was removed).
overflow:hidden on <html> — Clips position: fixed children in Firefox and some mobile browsers. Never use it on the root element to block scroll.
overflow:hidden on <body> (iOS Safari) — Body overflow manipulation breaks position: fixed element background rendering on iOS Safari, causing content to bleed through overlays. Use touch-action: none on the overlay element instead.
